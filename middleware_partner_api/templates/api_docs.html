1. Log in (get a token)

Most requests need a token. Get one with your username and password:

curl -X POST {{ base_url }}/partner_api/api-token-auth/ \
  -d "username=YOUR_USERNAME&password=YOUR_PASSWORD"

Response:

{"token": "9944b09199c62bcf9418ad846dd0e4bbdfc6ee4b", "expires_at": "2026-10-23T00:15:21Z"}

Then send it on every request

Authorization: Token 9944b09199c62bcf9418ad846dd0e4bbdfc6ee4b

Tokens expire 2 days after they are issued. When a request returns “Token has expired”, log in again to get a new one.

2. How the resources work

Resources support these calls (each card below lists the ones it has). Replace {id} with a record id.

MethodURLWhat it does
GET…/List records
GET…/{id}/Get one record
POST…/Create a record
PUT…/{id}/Replace a record (send all required fields)
PATCH…/{id}/Change only the fields you send

Linked records (country, event type, model runs, …) are sent as their id, or a list of ids. Event and risk lists come back 25 at a time: add ?page=2 for the next page.

Send email

Send an email from GEM OPM <opm@spc.int>. message can be plain text or HTML.

/partner_api/v1/mailer/send/   Token needed · POST only

Fields

FieldType
recipientslist of emails (1–50)required
subjecttextrequired
messagetext or HTMLrequired

Example

curl -X POST {{ base_url }}/partner_api/v1/mailer/send/ \
  -H "Authorization: Token YOUR_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{{ email_example }}'

Errors come back as JSON with the problem per field, e.g. {"title": ["This field is required."]}.
